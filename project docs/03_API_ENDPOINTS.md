# API Endpoints

Two API surfaces: the **public API** (Go, called by frontend) and the
**internal API** (Python worker, called only by Go — never exposed to the
internet directly, should sit behind the same VPC / internal networking
and ideally require a shared internal secret header).

Base URLs: `api.neurofiq.in` (Go, public) — Python worker has no public
DNS entry, only reachable from Go within AWS's internal network.

## PUBLIC API (Go) — called by frontend

### Auth

| Method | Path | Description |
|--------|------|-------------|
| GET | `/auth/google/login` | Redirect to Google OAuth (identity only) |
| GET | `/auth/google/callback` | Exchange code, create/update `users` row |
| GET | `/auth/github/login` | Redirect to GitHub OAuth (`repo` scope) |
| GET | `/auth/github/callback` | Exchange code, set `github_connected=true`, store token per open decision in doc 02 |
| POST | `/auth/logout` | Clear session |

### Repos

| Method | Path | Description |
|--------|------|-------------|
| GET | `/repos` | List candidate's GitHub repos (filtered, forks hidden by default, ETag-cached) |
| GET | `/repos/search?url=` | Manual paste-URL lookup for a specific repo not in the default list |
| POST | `/repos/{owner}/{repo}/pin` | Pin a repo (enforces free=2 / paid=10 limit) |
| DELETE | `/repos/{owner}/{repo}/pin` | Unpin |
| POST | `/repos/{owner}/{repo}/analyze` | Go checks 7-day cache; on miss, Go does deterministic extraction then calls Python worker internally for the Claude portion (see doc 04) |
| GET | `/repos/{owner}/{repo}/analysis` | Get cached analysis result + status |

### Interview — Text & Voice

| Method | Path | Description |
|--------|------|-------------|
| POST | `/interviews` | Body: `{repo_full_name, mode, interview_type, camera_enabled}` → Go creates session, calls Python worker for batch question generation |
| GET | `/interviews/{session_id}` | Session state + questions so far |
| POST | `/interviews/{session_id}/answers` | Body: `{question_id, answer_text}` → Go calls Python worker for scoring/feedback |
| POST | `/interviews/{session_id}/complete` | Finalize session, Go triggers Python worker for report generation |
| GET | `/interviews/{session_id}/report` | Returns `candidate_reports` row |
| WS | `/ws/interview/{session_id}` | Voice mode: Go handles the WebSocket, relays audio to Deepgram/ElevenLabs, calls Python internally per turn (see doc 05) |

### Camera / Recording

| Method | Path | Description |
|--------|------|-------------|
| POST | `/interviews/{session_id}/consent` | Record explicit consent before camera/recording starts |
| POST | `/interviews/{session_id}/video-chunk` | Chunked video upload (every ~10s), Go receives + forwards to storage |
| POST | `/interviews/{session_id}/finalize-video` | Go merges chunks, triggers storage + optional playback prep |
| POST | `/interviews/{session_id}/proctoring-event` | Client reports event from browser-side MediaPipe / Page Visibility API |
| GET | `/interviews/{session_id}/recording` | Get playback URL (candidate's own recording only) |
| DELETE | `/interviews/{session_id}/recording` | Candidate-initiated deletion (GDPR right to erasure) |

## INTERNAL API (Python FastAPI worker) — called only by Go

Every internal call from Go MUST include:
- `X-Correlation-ID` header (generated by Go per request, propagated through
  logs on both sides — see doc 12)
- `X-Internal-Secret` header (shared secret, not exposed to frontend)

| Method | Path | Description |
|--------|------|-------------|
| POST | `/internal/analyze-repo` | Body: `{structure_summary, code_snippets, repo_size_kb}` → returns `{languages, frameworks, architecture_patterns, complexity, quality_signals}` — stateless, single Claude call |
| POST | `/internal/generate-questions` | Body: `{analysis_json, difficulty_mix}` → returns 5-10 structured questions as JSON |
| POST | `/internal/evaluate-answer` | Body: `{question, candidate_answer, rubric}` → returns `{score, feedback, needs_followup, followup_question?}` |
| POST | `/internal/generate-report` | Body: `{session_questions_with_scores}` → returns `{overall_score, strengths, weaknesses, improvement_suggestions}` |
| POST | `/internal/voice-turn` | Body: `{transcript, session_context, question_history}` → returns `{ai_response_text, is_followup, move_to_next}` — used by Go's WebSocket relay per voice turn |
| GET | `/internal/health` | Basic liveness check, returns 200 if the worker can reach Claude API |

The Python worker never touches Postgres and never receives raw GitHub
tokens — Go does all data fetching/persistence and passes the worker only
the minimal structured payload it needs for the AI call.

## Rate Limits Per Endpoint (enforced in Go, single source of truth — doc 08)

| Endpoint | Free tier | Paid tier |
|----------|-----------|-----------|
| `POST /interviews` | 5/month | unlimited |
| `POST /repos/.../analyze` | 10/day | 50/day |
| `POST /interviews/{id}/answers` | 1 per 3 sec (anti-spam) | same |
| `POST /interviews/{id}/video-chunk` | n/a (paid-only feature) | rate-limited by session duration cap |

**Critical rule:** the Python worker performs no rate-limit checks of its
own. Go checks and increments usage counters BEFORE calling the Python
worker, atomically, to avoid the race condition described in doc 08.
